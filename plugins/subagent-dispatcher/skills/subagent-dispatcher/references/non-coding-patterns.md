# Non-Coding Patterns

## Multi-Source Research

Split by source type or topic axis:
- Official docs or primary sources.
- Community reports or user feedback.
- Pricing, limits, and operational constraints.
- Risk, compliance, or security considerations.

Use explorers. The main agent should browse or verify unstable facts when needed, then synthesize.

## Product Or Vendor Comparison

Split by vendor when each vendor can be evaluated independently. Split by comparison axis when the vendor list is large.

Good lanes:
- Features and workflow fit.
- Pricing and usage limits.
- Integrations and ecosystem.
- Risks, lock-in, reliability, and support.

## Document And Knowledge Review

Split by document, section group, or question. Ask each explorer for exact citations or page/section references when possible.

The main agent should combine the findings into a single answer, not paste independent summaries back-to-back.

## System Or Account Diagnosis

Split by evidence lane:
- Current config.
- Logs or command output.
- Installed plugins, apps, or tools.
- Historical state or prior sessions.
- Runtime process or network status.

Prefer read-only explorers first. Use workers only after the likely fix area is known.

## Creative Or Strategy Work

Split by direction or audience:
- Option A: conservative, low-risk path.
- Option B: high-speed path.
- Option C: differentiated or ambitious path.
- Reviewer: critique assumptions and blind spots.

The main agent should preserve a point of view and choose a recommendation.
